# 项目目标与开发路线

## 1. 项目定位

在现有 Music Resource Management System 上，开发供视频创作者 / 校园媒体选择配乐的 Music Discovery Platform。用户用描述或参考音频查找素材，检查元数据约束，并直接试听匹配片段。

示例：“找节奏明显、适合赛车集锦的器乐”，或“找与这段参考音频氛围接近的曲目”。音乐语义相似与“同一录音识别”不同；首版不承担翻唱识别或版权判定。

事实基线：2026-10-19 核对提交 `b81f57c79e1cefb96c2055df4ae438aa24fb475c`。当前有 Java / Vue 管理、上传、审核、分类标签、播放与回收站代码；没有 CLAP、Python 检索模块和片段索引。现状证据及运行结果在 README / STATUS。

## 2. 第一轮成功标准

- 从几十首可合法用于开发的素材开始；每条素材有稳定资源 ID、内容哈希、来源及许可记录。
- 文字查询可以返回实际相关曲目和有效时间片段；参考音频查询沿用同一嵌入空间。
- 保留旧列表筛选，增加独立 discovery 页面 / API；结果能定位并试听片段。
- 对比元数据关键词、整曲向量、片段向量和融合方案；保留失败案例，按 held-out 查询报告结果。
- 环境、数据清单、模型 / 预处理版本和运行命令可由另一个账号复现。
- 搜索、参考音频、导入状态和试听具有明确权限；删除或拒绝审核后不再由共享检索暴露。

上述是待完成验收，不是当前能力。

## 3. 第一轮范围

必须：恢复旧系统可重复启动；固定接口；音频解码 / 切片；预训练模型接入；精确检索基线；时间戳试听；基本元数据过滤；离线评测；导入状态和失败反馈。

后续：扩大语料、可恢复处理、索引版本切换、并发性能与故障验证、少量真实用户任务反馈。

暂缓：多人协作、个性化推荐、复杂多租户、微服务全面拆分、自训练基础模型、版权判定、完整 DAW / 在线音频编辑器。音频去重作为后续独立方向，不抢占首轮检索范围。

“先抑后扬”“没有人声”等描述可能超出单一 embedding 的可靠能力。把时间结构、否定条件、中文查询作为明确测试类别；不宣称模型已解决。首版自然语言基线先用英文查询，中文支持另建评测子集，再决定是否需要翻译或专门模型。

| D-005 | 建议契约，MUS-002 冻结 | 10 秒窗口、5 秒步长；单声道；采样率以最终 checkpoint 的预处理要求为准；端点见 CONTRACTS |

## 5. 规模与目标的边界

| 内容 | 类型 | 说明 |
|---|---|---|
| 30–50 首 | 最小闭环建议范围 | 先验证处理、检索、时间定位和试听 |
| 1,000–3,000 首，示例 2,000 首 | 扩展计划 | 以素材许可、处理成本和硬件情况决定 |
| 约 70,000 个片段 | 算例 | 假设 2,000 首、每首 180 秒、10 秒窗口 / 5 秒步长；实际按解码时长统计 |
| 120 条查询，80 开发 / 40 测试 | 评估计划 | 全部都是待整理数据，不是已有标注；最终参数只使用开发集选择 |
| 检索 P95 ≤300ms、20 并发客户端 | 候选工程目标 | 从已编码查询向量进入检索开始，包含筛选 / 排序；完整端到端另测 |
| nDCG@10 相对整曲基线提升 10% | 实验目标 | 可能不成立；如实报告差异，不调整测试集以制造提升 |

不以扩大量级代替解决问题，也不将目标直接写成实测简历指标。

## 7. 证据与实验规则

每次运行保存：代码 SHA、命令、数据 manifest 哈希、模型哈希、预处理和索引版本、设备、依赖锁、开始时间、原始输出和失败计数。大文件存外部 / 本地工件位置，仓库只记录可获取的位置及校验值；不要求另一账号拥有相同绝对路径。

- 标注以 query–track 和 query–segment 关联；相关性等级按 CONTRACTS。
- 对比时固定候选库和查询划分；先有整曲 / 关键词基线再引入融合。
- CLAP 可能在预训练中见过公开音乐；无从核实则报告此局限，不声称预训练级无泄漏。
- 测试查询不用于窗口、排序权重或阈值选择；人评候选池覆盖多个系统，减少只评价自己返回项的偏差。
- P50/P95、错误率、索引大小、建库时间、内存和完整查询耗时分别记录，不混淆模型时间与检索时间。
- 检索质量没有提升也有价值：记录失败原因和效果 / 成本取舍，不补造结果。
