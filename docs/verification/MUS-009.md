## 问题与实现

旧控制器将客户端 chunkMd5 原样入库；ChunkCacheService 在 save=false 或写库异常后仍返回，且即时 save 后继续调用未注册 SQL 的 insertBatchSomeColumn。旧合并计算了 MD5 却没有比对声明值。

本任务取消缓存、定时 / 关闭钩子和自定义批量映射，使用标准 CRUD。UploadIntegrityService 的公开上传 / 合并方法使用 Spring 事务与上传行 FOR UPDATE 锁，避免同 fileId 的并发重试重复计数；分片与计数写失败均抛出，控制器在事务代理返回后才成功 ACK。未新增依赖或 schema。

分片先写唯一临时文件并同步数据，按实际文件大小 / MD5 验证；同内容重试只保留一条记录，冲突内容拒绝覆盖，原内容可修复缺失 / 损坏分片。进度来自成功数据库记录。合并要求索引完整连续，逐片校验，再比对整文件总大小 / MD5；重复合并复用已完成路径。临时源文件只在事务提交后清理，明确回滚时清理新文件；事务结果未知时保留文件供后续核对。

校验失败保持 status=0、无完成路径返回。公共路径、字段和旧 envelope 保留，详情见 CONTRACTS A3。

