## 实现与接口边界

- `discovery_build.py` 和 `build_discovery_index.py`：严格私有 catalog/source proof，校验字符串 Java Long ID、bytes/MD5/SHA256、来源/CC BY4/attribution 与原快照，拒绝链接、越界、重复、改动或旧输出；实际 MP3 读到 EOF，单/双声道平均，一次 soxr_hq 重采样48kHz，确定10s窗口/5s步长和尾窗，右补零且时间不含补零。每小批真实 CLAP 编码，整曲为归一化片段均值。
- 生产 manifest 新增必需 `build_proof_sha256`，关联 `build-proof.json` 的数据、源码、模型/cache、PCM和逐窗口边界。先重验原资产/源码/权重与实际消费者，再激活 manifest；失败仅留私有部分输出，重跑拒绝覆盖。没有自动切换运行服务索引。
- `discovery_index.py` / server：生产加载复核证明和固定recipe、源/特征、CLAP A及离线cache身份；构建和查询cache必须一致。完整文本校验实际 token ID、EOS、mask/padding，不使用SDK默认77截断；>256明确400。既有合成模式仍须显式启用，原14项检索回归通过。
- `verify_discovery_runtime.py`：固定两短描述及一条长描述，真实 SDK / 私有 HTTP、两mode和独立余弦公式复算，检查空/子集/过期内容、auth、版本、实际token边界；无qrels、自动质量标签或模型选择。
- `prepare_discovery_assets.py` / [固定资产计划](MUS-068-assets.json)：仅显式 `--download` 在全新B目录准备固定内容，或 `--verify-only` 只读校验。权重/两曲/cache全部固定pins，预算/部分输出/重试保护；工作进程不调用下载工具。通用完整下载流程以假HTTP跑通并由真实资产只读验证，未额外重新下载整包；首次真实获取另留原始收据。
