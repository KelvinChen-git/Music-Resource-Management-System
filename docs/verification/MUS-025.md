## 使用

1. 打开本机Sonora的`http://127.0.0.1:5175/research/review`，或侧栏“试听审阅”。先登录标注包归属账号；本机真实51对包归属已有演示普通账号，不是给所有账号共享的资源。
2. 点“导入标注包”，选择本checkout `.local/a/mus024/review-pack.json`。文件只在浏览器解析，不上传服务器；未知包须先用[MUS-024 CLI](MUS-024.md)生成并对固定运行校验。本页校验结构/owner/内容指纹，不认证来源报告真实性。
3. 选查询与候选，试听整曲或模型建议片段。每次重新GET现有JWT媒体接口，核对完整字节数/SHA后才创建Blob URL；停止、切候选、切包、离页或退出会释放媒体。不会在URL附JWT或用pay增加播放计数。
4. 实际听音后填写匿名代号，明确选择0不相关/1弱相关/2相关/3高度相关。评分才写入UTC操作时间；未判断仍null。可从成功试听位置取点，人工区间须另点保存，不能自动采用模型建议。保存会替换本条已有人工区间。
5. 草稿按当前账号与dataset指纹保存。重新导入先保留文件内容，需点“恢复本机草稿”才替换。存储失败时会提示导出；本轮未注入真实quota故障。退出清内存/音频，草稿仍留本机该账号槽；没有跨设备同步或服务端标注接口。
6. 随时导出部分判断JSON，再用MUS-024 `validate --pack <导出文件>`对原run固定report SHA检查。浏览器校验与最终CLI都是格式/一致性检查，不证明标注者身份或是否真人听音。

仅增加本视图、两个helper及对应测试，App侧栏一项与router一条登录路由。原Sonora布局、全局播放器队列、管理页面和媒体helper未重写；Java/Python处理器/API/schema/锁文件/公共目录不变。

## 限制与交接

所有真实51条仍全null，没有人评质量/时间IoU/P95/held-out或discovery-v0冻结。模型建议可见，有提示偏差。捕获位置为浏览器事件状态，片段停止为事件/定时机制，非采样精确剪辑。每次重播重新鉴权；无法撤回已经合法交付的音频字节。

真实浏览器只做同账号退出/重登与错owner文件拒绝；未新做账号撤权媒体矩阵、两真实账号切换、存储quota失败或两个真实播放器竞争。取消/晚响应/晚play promise/重播和全局播放器pause hook由fake audio/fetch检查；JWT header由既有6项helper检查，未另抓实际网络包。本轮没有后端重启/数据库迁移、账号或资源写操作，也未跑无关Maven/CLAP/全离线模型套件。

下一步由B按准确SHA补独立隔离环境复核，真人再使用该入口判断候选；不能让自动化或模型代填真人结果。原版和现有MUS-014后端继续保留，不合并main。
