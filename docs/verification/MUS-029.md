# MUS-029：整曲与片段排序的首次探索比较

本轮8条描述上，片段排序每次前5首平均有2.25首被用户评为相关/高度相关，整曲排序为2.00首。差异来自电子舞曲与爵士两条描述各多1首，其余6条相关数量相同。按已判池归一化的排名得分，片段5条更好、整曲3条更好，不能归纳为所有描述都获益。

这只是同20首音乐、同8条探索描述和可见模型建议下的人评结果；不据此冻结模型或宣称正式质量验收/10%提升。实施 `ef5e38842c6d0cf632d7401d77a61271fb8eb50d`；比较/协议基线 `c206567055416832a67ceead67c922452aefa71d`；owner A，分支`codex/MUS-029-exploratory-evaluation`。源码仅新增标准库evaluate_review.py及独立合成test；原检索、标注、播放器不变。

## 固定口径

按[CONTRACTS E4](../CONTRACTS.md)先固定方法再实现/比较：

- 回到原run的rankings.json顺序，读取整曲/片段各top5；包内按曲目ID的展示顺序不当排名。原run已有确定性tie顺序，本轮各5首没有score相等。不跨mode比相似度分值。
- P@5把用户2或3分视为正相关、固定除5；0/1均未达此标准。
- pooled nDCG@5：DCG为sum((2^rel−1)/log2(rank+1))，IDCG为同query两mode已判并集按等级降序的最佳5；1分仍有gain=1。IDCG=0时nDCG=null，披露并排除该项宏均值，P@5仍计0。本次无零IDCG，均为8条等权宏均值。
- 报告和完成标注各需要显式SHA；从固定report/catalog重建不可变候选并全量验证。缺判、重复/未知ID、候选/哈希漂移、短top5拒绝，绝不把未判当0。

指标背景参考作者提供的[排名评估章节](https://nlp.stanford.edu/IR-book/html/htmledition/evaluation-of-ranked-retrieval-results-1.html)及[候选池相关性判断说明](https://www-nlp.stanford.edu/IR-book/html/htmledition/assessing-relevance-1.html)。本轮明确选择指数gain和已判并集归一化，不宣称与其他工具默认gain或全库真值相同。

## 低分与下一步诊断

原声吉他、摇滚、慢速钢琴、爵士、紧张管弦乐五条描述的已判池各只有1个2或3分曲目，优先检查这些场景。单凭当前结果无法区分：库中缺少满足条件的曲目、模型没选中已有合适曲目，或描述同时要求乐器/情绪/节奏导致不满足全部条件。

当前8×20=160个可能对只判了top5并集51个，另109个未知；其中这5条弱描述还有67个未入池对未判。建议先对它们做有界人工核查：若有漏召回正例，保留为排序失败案例；若确认库中仍无足够素材，再按原声吉他/钢琴、摇滚、爵士萨克斯、管弦张力等条件补充来源与许可清晰的完整曲目。两类情况均可并存，不能将未判直接当不相关。

本轮尚无全库确认的“确实无匹配”query，不能由这8条直接定拒绝阈值。后续应另建版本、明确无匹配及易混淆描述，建立独立dev/test，不修改已收标签或用这批探索标签调参。没有自动扩库、外部下载、训练或新增标注包；逐曲原排名/既有标签的私有复查表在.local/a/mus029/private-cases.md。
