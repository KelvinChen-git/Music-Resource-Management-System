## 2. 数据与描述隔离

旧40曲及派生片段/转码/剪辑/参考音频、141标签、179个未判组合、8旧query及其翻译/同义改写、029–037的排名/失败案例与定向selection全部留在development。不能拆旧40、改dataset或不给看旧分就称独立测试。

新test至少5个未进入旧材料的作者/合作群，每群最多4首。按规范作者身份、别名、合作关系、同一作品的版本/cover/remix建立分组，整组排除或分配；单看artist字符串或文件SHA不能证明隔离。字节SHA查精确重复，作品/录音近重复审查须记录实际使用的方法与版本；若只做元数据/人工审查就如实写，不能称已完成全音频指纹排重。关系不明先隔离，不进test。

新query正文、中英文解释、关键可听特征与0–3规则先于作者查看新候选或任何新模型排名冻结。query写作步骤不得查看新候选；素材选择接口不得接受query文本、人评或模型分数。旧句换词/翻译不算新意图。宽泛风格词相同不自动等于同一意图，但须人工记录新组合与旧意图的区别，不能仅凭文本hash称已语义去重。

素材采样框是未来冻结的可许可音乐元数据快照。提供方、纳入条件、枚举范围、元数据快照与SHA须在新query正文编写或向采样方披露之前冻结；框内不得由query派生标签/作者白名单定向挑源。query作者不得查看框内候选，不能按每条query凑正例。先排除旧/相关作者与作品组，再用计划中的固定SHA256优先序，遵守每群4首上限取20；不因无正例或模型分低换曲。许可/证明不全、身份不明、重复、解码无效、时长或大小越界才能按同一冻结替补队列替换，并保留全部排除原因。替换仅能发生在数据冻结及任何test运行/标注之前；之后出错应中止该版本并记录，不能静默换样本。若冻结框内不足20曲或5个合格群则blocked或另立方案版本，不能放宽旧群排除/作者上限或为相关性重挑采样框。

音频边界仍MP3、30–600秒、≤30MiB；时间采用固定65536 float32 out读取至实际EOF，declared/header另存。新test所有provider使用同一实际解码版本，不能直接沿用旧“某provider用历史头部”的分派。两检查点共享完全相同的解码/48k整数ceil重采样输入、10秒窗口5秒步长/尾零填充和量化规则，分别编码，不能混用两个checkpoint的向量。

8条新描述以英文进入模型，中文只作冻结的标注解释。其中2条为可能无匹配的边界需求，计入总8条；实际零正例由完整人评决定。出现匹配后不改句、删曲或强改标签。现有文本骨干的官方模型卡以英语预训练为说明，不能由当前英文结果保证中文检索。[RoBERTa模型卡](https://huggingface.co/FacebookAI/roberta-base)

官方将二者列为HTSAT-base、无fusion的同家族发布；这使架构保持一致，但不能把权重差异的结果严格因果归因于“加入speech”。文件名中的数字属于发布名，不是Sonora成绩。[官方模型说明](https://github.com/LAION-AI/CLAP#pretrained-models)、[固定发布元数据](https://huggingface.co/api/models/lukewys/laion_clap/revision/b3708341862f581175dba5c356a4ebf74a9b6651?blobs=true)

词面基线只使用提前冻结的原始标题，不加query定向标签/作者风格/人工解释。NFKC+casefold，`[a-z0-9]+`单词，不分词扩展/词干化/停用词表；tf=`1+ln(count)`，idf=`ln((1+N)/(1+df))+1`，L2归一化cosine。词表和df从待检索的20个**无标签标题**建索引，query/qrels不参与df，公式不能看test改；这不是在test标签上学习。未知词忽略、零query向量得分全0，按固定数值Java track ID排并列，不自动输出相关/不相关。它较弱不能单独证明声学模型先进。

## 4. 标注与单次解封

使用全8×20矩阵，不用任何模型top-k池决定哪些对值得标。[NIST对test collection及pooling的说明](https://trec.nist.gov/pubs/trec33/papers/overview_33.pdf)是本次选完整小矩阵的依据；本项目不采用“未入池即负例”假设。

标注者先用development练习可听特征与规则：0明确不符，1仅少量关键特征，2多数关键特征，3明确吻合；没听清/不理解保持null或新格式的无法判断状态，不能补0。相关区间不作为首批任务，不能用track级成绩认证片段定位。呈现固定为批次1→4、批内按声明query顺序、每条query内按预定SHA256升序再按recording_key破同值，不能全160条全局打散；隐藏模型名、分数、排名与模型片段；标题/来源署名仍可见，其提示效应需披露。这是model-blind单用户主观判断，不是双盲或已通过标注者一致性验证。

首批160是唯一组合数，计划不要求另招第二人。可选16对第二人/重复检查默认未启用，不计入160；若要启用，须在标注前冻结抽样、额外工作量和分歧处理，不能看模型错例后挑选。无第二人时明确单标注者限制。任何无法判断未解决时保留未知，报告未完成；不能为凑160而强填或删除query。

流程按门槛依次执行：

1. **G0：本方案与机器计划提交**；仅设计完成。
2. **G1：先冻结采样框，再由未看候选的作者冻结新query，最后按固定队列收20曲/作者作品组/实际EOF与排除记录**；均须新manifest SHA。不足20曲/5新群则blocked，旧材料只能排除/预检，不迁移为test。
3. **G2：dev预检通过后发布运行冻结收据**：双方本地权重、源码/依赖/环境、共同DSP、5配置、协议/数据/query/分组与呈现hash齐全；发生在任何test模型运行与可读test qrels打开之前。
4. **G3：生成新格式的model-blind全矩阵包，按四批收件**。标注者保管可读原始test导出直到G5，在标注者侧校验；G5前运行方仅收dataset/payload SHA、总完成数量与合法性状态，不收可读qrels正文/路径、grade分布或逐query正例数。旧CLI会输出等级分布，不能直接作提前交回test标签的入口。hash只是完整性承诺，不是访问控制，必须记录实际保管和打开步骤。
5. **G4：全部160个合法判断完成，五配置的无标签排名均持久化并hash**；任一缺失则未完成，不看部分质量决定是否补齐。
6. **G5：G2收据与G4全部160合法判断/五runs hash齐全之后，才向运行方交付可读qrels并一次解封、固定输入比较与独立复算**，报告全部配置。若据test修改模型、prompt、语料或指标，该test以后只作development回归，下一版本另建保留集。[关于test不参与模型选择的官方实践](https://scikit-learn.org/stable/common_pitfalls.html#data-leakage)

## 5. 冻结的指标与完成条件

主指标macro P@5：等级≥2，分母固定5，8条query等权，包括零正例query（贡献0）。完整160对才给正式精确成绩；任何未知不能当负例，也不能从均值删除该query。

次指标nDCG@5：gain=`2^grade−1`，discount=`1/log2(rank+1)`，IDCG从完整20曲中取最佳5。IDCG=0时该query返回null，只在nDCG宏值中排除并披露数量/哪些query；P@5仍纳入全部8条。**zero-positive不等于zero-IDCG**：全1分时无二值正例、P@5=0，但所有gain都为1，完整任意排序的nDCG@5=1，不能把高nDCG单独当存在好匹配。

报告每query的相关曲数与P@5理论上限`min(R,5)/5`、实际零正例/零IDCG/未知数量，全部5配置的逐query/宏分数、预注册差值和胜/平/负，用绝对百分点。样本单位是8条query，不能把40个top5位置当40个独立样本。首批不报告统计显著/广泛泛化、Recall、定位IoU、P95、中文准确率或拒绝检测通过；不把cosine当概率，不用仅有正例的dev子集校准拒绝阈值。

执行验收要求全部输入完整、隔离与冻结收据通过、160合法判断、5固定runs与独立复算一致；**成绩不提升也能完成有效评测**，不预设100%或10%提升。小样本结果本身不自动完成MUS-002正式模型验收、discovery-v0冻结、上线或main合并。
